## 5. 실무 체크리스트

### A. 비회원·단순 파라미터 조회 API

- **인가 검증(BOLA/IDOR)**: 요청자가 그 리소스의 소유자인지 매 요청마다 확인합니다. `?no=12345` 같은 식별자를 그대로 신뢰하지 말고 세션 주체와 바인딩합니다.
- **식별자는 추측 가능하다고 가정**: 운송장 번호·주문번호·회원번호는 순번·규칙성이 있는 경우가 많습니다. 무작위화하거나 1회용 토큰으로 바꿉니다.
- **호출량 제한**: 계정·IP·디바이스 단위 rate limit, 동일 주체의 연속 열람·대량 조회 탐지·차단.
- **응답 최소화**: 한 화면에 성명·주소·전화번호를 한꺼번에 주지 않습니다. 마스킹과 개별 확인 단계를 둡니다.
- **해외 IP는 상시 정책으로**: 사고 후 차단이 아니라, 국내 서비스라면 기본 거부 + 예외 허용으로 설계합니다.
- **로그**: 조회·인증 로그 90일 이상 보존, 짧은 시간 다건 조회에 알림.

### B. 돈이 움직이는 API (송금·정산)

- **이상 출금 룰**: 금액·횟수·신규 수취 계좌·야간 시간대 조합으로 차단. 90여 차례 반복을 막는 것은 인증 강화가 아니라 거래 룰입니다.
- **다회 호출 차단**: 동일 세션·토큰의 연속 출금 요청에 지연(hold)과 재인증을 겁니다.
- **자격증명 분리**: 운영 계정과 서비스 계정을 나누고, 서비스 계정은 IP allowlist + 최소 권한.
- **정산 계좌 변경**: 2인 승인, 등록된 연락처로 콜백 확인, 변경 후 24시간 출금 보류.

### C. 사칭 문자·전화 (2차 피해)

- 유출 직후가 가장 위험합니다. **공식 채널을 먼저 고지**하고 임직원·고객에게 같은 문구로 알립니다.
- "우체국 주소 변경 요청", "추가 배송비 결제" 링크는 열지 않습니다. 우체국은 변경서비스를 임시 중단한 상태이며, 문의는 우편고객센터로 받습니다.
- 다나와·공제회 사칭 전화·문자도 같은 방식입니다. **기업은 전화·문자로 비밀번호·결제정보를 묻지 않는다**는 원칙을 공지문에 명시합니다.

### D. 사고 공지 운영

- "점검" 공지에서 "침해" 공지로 바꿀 때, 바꾸는 시점과 문구를 명확히 합니다. 다나와 사례는 이틀 동안 회원이 점검으로만 인지했습니다.
- 신고 시한: **침해 인지 24시간 이내**(정보통신망법), **1,000명 이상 유출 시 72시간 이내**(개인정보보호법) 통지.
