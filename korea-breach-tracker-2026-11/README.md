[한국어](README.md) | [English](README_en.md)

2026년 9월 말부터 11월까지 국내 금융·공공·유통·대학에서 확인된 유출 사고를 한 문서에 모았습니다. 개별 사건의 규모보다 중요한 것은 **어디서 뚫렸는가**입니다. 핵심 계정계가 아니라 외부 위탁, VOC 첨부파일, 레거시 연동, 가맹점·정산 접점이 반복해서 뚫렸습니다.

**CJ올리브영** — 11월 23일 외부 비인가 접근으로 업무시스템이 침해됐습니다. 임직원 639명·협력사 106명·일반 고객 45명, 합계 790명의 이름·이메일·휴대전화번호·생년월일과 **내부 관리용 회원번호 자료 2,406,338건**(회원번호만 2,344,549건 + 회원번호·접속 IP 61,789건)이 유출됐습니다. 결제정보와 비밀번호는 노출되지 않았고, 시스템 격리·계정 회수·관계기관 신고를 마쳤다고 공지했습니다. 실무 포인트는 **백오피스 계정과 내부 관리용 식별자**입니다 — 고객용 앱이 아니라 직원·운영 계정이 들어가는 문이었습니다. 상세 점검표는 [`cj-oliveyoung-breach`](../cj-oliveyoung-breach/README.md)에 있습니다.

**다나와** — 11월 26일 02:00부터 웹·앱 서비스가 중단됐고, 보도에 따라 15~17시간 이상 이어졌습니다. 회사는 외부 침해를 추정하며 개인정보 유출 여부·규모를 조사 중입니다. **확인된 것과 확인되지 않은 것을 섞지 않는 것이 이 건의 핵심**입니다(유출 미확인 ≠ 무유출). 이용자·운영팀 체크리스트는 [`danawa-service-outage`](../danawa-service-outage/README.md)에 정리했습니다.

**Sh수협은행** — 11월 26일 오후 고객 54명의 대출 정보·신용정보·주소 등이 유출된 사실을 확인해 금융감독원에 보고했습니다. 공격자는 다수의 주민등록번호로 반복 접속했고, 주민등록번호만으로는 접근할 수 없지만 **추가 인증에 필요한 서비스 코드를 난수로 대입해 맞히는 방식**으로 조회한 것으로 알려졌습니다. 해외 IP 공격으로 추정되며 경로·원인은 조사 중입니다. 이 사고로 AI 활용이 의심되는 금융권 해킹에서 피해가 확인된 은행은 신한·KB국민·하나·BNK부산에 이어 **5곳**으로 늘었습니다. 10월 17일 국립부경대 등록금 수납시스템(5,108명) 사고와는 별건입니다.

> 수협은행 건의 실무 교훈: **주민등록번호 + 짧은 숫자 코드** 조합은 난수 대입에 취약합니다. 조회 API에 사용자 단위 시도 제한·실패 지연·이상 조회 패턴 탐지를 걸고, 대량 조회는 별도 승인 절차로 분리해야 합니다.

**호텔스토리** — 숙박 예약관리(PMS·채널매니저·부킹엔진) 솔루션 기업이 10월 26일 1차 침해에 이어 **11월 22일 자체 시스템 취약점을 악용한 2차 침해**를 당했고, 11월 23일 유출 사실을 확인했습니다. 첫 침해 이후 **27일 만**입니다. 2차 유출 항목은 숙박 예약정보(성명·휴대전화 또는 안심번호·이메일·예약번호·예약 상태·숙박정보)와 부킹엔진 회원정보(성명·전화번호·이메일)입니다. 예약이 호텔스토리 시스템을 거쳐 처리됐다면 직접 가입한 적 없는 고객도 대상에 포함될 수 있는데, 회사는 피해 숙박시설·예약 플랫폼 명단과 전체 규모를 공개하지 않았습니다. 1차는 노출된 숙소 계정정보가 경로였고 2차는 자체 취약점이었습니다 — 비밀번호 초기화·접근권한 점검 같은 1차 조치가 취약점 자체를 없애지 못했다는 뜻입니다. 숙박정보는 이동·체류 일정을 드러내므로 예약번호를 넣은 사칭 취소·추가 결제 메시지에 특히 주의해야 합니다.

**한전 유출본 유통** — 11월 23일 한 해커가 텔레그램 채널에 한전 유출 고객정보를 판매한다는 글을 올렸고, SBS 취재진이 구매자로 가장해 접촉한 결과 실제 이번 침해로 유출된 정보였습니다. 해커는 약 **104만 건**을 보유했고 그중 20만 건은 이름·계좌번호·주민번호·전화번호·주소가 모두 포함됐다며 **건당 500원**에 팔겠다고 했습니다. 한전도 판매 중인 정보가 이번 공격의 유출본이 맞다고 확인했습니다. 다크웹에서만 거래되던 자료가 일반 메신저로 넘어온 것으로, 접근 장벽이 낮아진 만큼 유출 항목을 조합한 피싱·보이스피싱 위험이 커집니다.

### 2-2. 같은 기간 국외 5건 — 전부 '자격증명'에서 시작됐다

- **1Password**: 직원의 기업 GitHub 계정이 침해돼 비공개 소스코드·CI/CD 접근과 백엔드 악성코드 배포로 이어졌습니다. 4대 통제와 점검 스크립트는 [`1password-github-breach`](../1password-github-breach/README.md).
- **Rackspace Spot**: 탈취 자격증명으로 고객 클러스터에 파드를 만들고 Secret을 열람했습니다. 플랫폼은 12월 8일 종료를 공식화했습니다. IoC·키 회전 순서는 [`cloud-secrets-exposure`](../cloud-secrets-exposure/README.md).
- **Defang**: 개발·테스트용 GitHub App이 필요 이상의 권한(배포 환경 변경 포함)을 갖고 있었고, 그 App으로 릴리스 태그를 단 커밋이 **릴리스 태그를 신뢰하는 프로덕션 CI**에서 실행되며 운영 자격증명이 복사됐습니다. 자격증명은 11월 23일 교체 전까지 유효했습니다(회사 공지).
- **Hex.pm**: `application/vnd.hex+erlang` 본문 파서가 `__struct__` 키를 가진 맵을 통과시켜, 라우팅·인증 전 단계에서 역직렬화 RCE가 가능했습니다. 69개 요청으로 서버 6대가 영향, 회사는 **20분 내** 서버측 패치를 배포하고 자격증명을 교체했습니다. 비밀번호·2FA 재설정 권고가 나왔습니다.
- **EU 집행위**: AI 에이전트 연계 공격(ARTEX/Storm-0940)으로 지목된 사건으로, 10월 22일부터 진행 중이며 직원 전체 유출 증거는 확인되지 않았습니다. 분석 링크는 [`ai-agent-attacks`](../ai-agent-attacks/README.md).

## 4. 사내 점검 체크리스트

### 4-1. 조회 API — BOLA/IDOR

- [ ] 모든 조회 API에서 **세션 사용자 == 리소스 소유자** 검증 (ID를 받아 그대로 조회하지 않기)
- [ ] 리소스 ID는 순차 번호 대신 UUID v4 등 추측 불가 값
- [ ] 목록·검색 API에도 동일한 소유자 스코프 적용 (필터 우회 확인)
- [ ] 대량 조회에 **사용자·토큰 단위 카디널리티 제한** (IP 단위만으로는 부족)
- [ ] 비정상 대량 SELECT를 WAF·DAM에서 탐지·차단

### 4-2. 첨부파일 (VOC·게시판·상담)

- [ ] 다운로드 API마다 작성자·권한 검증
- [ ] S3·NAS 버킷 퍼블릭 차단, **짧은 만료 Presigned URL**로만 제공

### 4-5. 외부 접점 3원칙 — ACT · ROT · LOG

이번 달 사고들이 반복해서 가리키는 세 가지입니다.

| 원칙 | 할 일 | 판단 기준 |
| --- | --- | --- |
| **ACT** | 도메인·구형 시스템·관리자 페이지·백오피스까지 **외부 접점 자산 목록화** | 인증서 투명성(CT) 로그·서브도메인 열거로 모르는 자산 찾기, 폐기 시스템의 DNS 레코드 회수 |
| **ROT** | 키·토큰·자격증명 **정기 회전 체계화** | 발급처 순서로 회전, 회전 후 CloudTrail·감사 로그로 잔여 사용 확인, CI는 OIDC로 전환 |
| **LOG** | 외부 접점 **인증 로그 90일 이상 보존** | 성공·실패 모두 남기고 대량 조회·비정상 시간대·해외 IP를 탐지 규칙으로 연결 |

> 3원칙은 새 통제를 만드는 일이 아니라, 이미 있는 자산·키·로그를 **목록으로 만들고 주기로 묶는** 일입니다. 사고 공지가 나온 뒤에야 목록을 만드는 조직이 반복해서 당합니다.

## 5. 공통 교훈

1. **핵심 DB는 지켰지만 주변 접점이 뚫렸다.** 외부 위탁·첨부파일·레거시 연동·백오피스가 반복 지점입니다.
2. **정상 토큰으로 반복 호출하면 인증은 통과한다.** 인가(권한)와 사용량 이상 탐지가 필요합니다. 주민등록번호+짧은 코드 조합은 난수 대입을 견디지 못합니다(수협은행).
3. **사고 공지의 규모는 줄어들 수 없다.** 한전은 1개월 만에 3.5만 명이 추가 확인됐습니다. 초기 발표를 최종 규모로 가정하지 마세요.
4. **국외 5건은 모두 자격증명에서 시작됐다.** 저장소 권한·CI 신뢰 조건·정적 키를 함께 줄이지 않으면 같은 형태가 반복됩니다.
5. **유출된 데이터는 공지 뒤에 시장에 나온다.** 한전 유출본은 사고 공지 사흘 뒤 텔레그램에서 건당 500원에 매물로 올라왔습니다. 노출 항목과 식별자를 기준으로 한 사칭·피싱 탐지와 고객 안내는 사고 종결 이후까지 유지해야 합니다.
