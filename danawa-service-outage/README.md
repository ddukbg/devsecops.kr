## 2. 확인된 사실

- **02:00부터 중단**: 커넥트웨이브 공지의 "중단 일시 2026년 11월 26일 (목) 02:00 ~" 와 복수 매체 보도가 일치합니다.
- **이유는 "외부 침해로 추정되는 보안 사고"**: 공지 원문은 "다나와는 외부 침해로 추정되는 보안 사고를 확인하고, 이용자 정보와 서비스를 보호하기 위해 서비스 이용을 일시 중단하고 있습니다"라고 밝혔습니다. 침해가 확정됐다는 표현은 아닙니다.
- **원인·영향 범위·개인정보 유출 여부 조사 중**: 공지에 명시되어 있습니다.
- **관계 기관 신고 절차 진행, 외부 보안 전문기관 조사 참여**.
- **안전이 확인된 서버부터 순차 재개**, 일정은 공지 페이지로 안내.
- **이용자 권고 2가지**: ① 다른 서비스와 동일한 비밀번호를 썼다면 변경, ② 다나와를 사칭한 전화·문자·이메일에 주의.
- **사칭 주의 문구**: "다나와는 전화나 문자로 비밀번호나 결제정보를 묻지 않습니다."
- **규모 참고**: 2022년 기준 모바일 MAU 약 723만 명(회사 발표). 장시간 중단으로 입점 판매업체·제휴 쇼핑몰 영업에도 영향이 예상됩니다.

## 5. 실무자 관점: 이 사고에서 볼 것

1. **"점검" 공지가 "침해" 공지로 바뀌는 패턴.** ZDNet은 점검 안내 문구가 침해 사고 공지로 교체됐다고 보도했습니다. 초기 공지가 사고 인지 **이전**에 나갔다는 뜻이고, 그만큼 신고 시한이 이미 흐르고 있었다는 뜻입니다.
2. **법정 신고 시한은 두 개가 동시에 돕니다.** 정보통신망법상 침해사고는 안 때부터 **24시간 이내** 신고, 개인정보보호법상 **1000명 이상** 유출 시 **72시간 이내** 개인정보보호위원회·KISA 신고입니다(ZDNet 정리). 사고 인지 시각을 기록하는 절차가 없으면 이 두 시계를 놓칩니다.
3. **외부 표면이 넓은 커머스 플랫폼.** 상품 DB·회원 DB·제휴 쇼핑몰·입점 판매자 연동에 더해, 최근에는 외부 AI(ChatGPT·Claude) 연동까지 붙었습니다. 연동이 늘어난 만큼 **인증·세션·DB 경계**가 느슨해지기 쉽습니다.
4. **중단이 곧 침해의 증거는 아닙니다.** 다만 이번처럼 전면 중단 + 외부 포렌식 투입 조합은 "격리 후 조사"에 가깝습니다. 이용자·입점사 커뮤니케이션을 먼저 준비해야 하는 상황입니다.

## 6. 이용자 체크리스트

- 다나와에서 쓴 비밀번호를 **다른 사이트·업무 계정과 같이 쓰지 않았는지** 확인하고, 같다면 지금 바꿉니다. (커넥트웨이브 권고)
- **"다나와 보상·환불·계정 확인·본인 인증"** 을 내세운 문자·전화·메일의 링크는 누르지 않습니다. 다나와는 전화·문자로 비밀번호나 결제정보를 묻지 않는다고 공지했습니다.
- 유출이 아직 확인되지 않았더라도, 다나와 가입 이메일로 온 **비밀번호 재설정 메일**은 직접 다나와에 접속해 처리합니다. 메일 안의 링크로 바로 들어가지 않습니다.
- 다나와에 저장한 **배송지·연락처**를 최근 사칭 택배·스미싱에 대조해 봅니다.
- 결제 카드를 다나와에 등록해 두었다면, 이상 결제 알림을 켜 두고 명세서를 확인합니다.

## 7. 서비스 운영팀 체크리스트 (DevSecOps)

### 외부 AI·커머스 API 연동을 확장할 때

- **연동 자격증명을 용도별로 분리**합니다. AI 연동용 토큰은 상품 카탈로그 **읽기 전용**이어야 하고, 회원·주문·결제 DB에 닿으면 안 됩니다.
- **세션을 넘기지 않습니다.** 외부 위젯·에이전트가 로그인 사용자의 세션 쿠키를 재사용하는 구조는, 연동 하나가 곧 계정 탈취 경로가 됩니다. 서버 간 호출은 별도 서비스 토큰으로 바꿉니다.
- **대량 조회를 이상 행위로 탐지**합니다. 가격비교·상품 수집은 정상 트래픽과 구분되지 않으면 침해와 크롤링을 둘 다 놓칩니다. 사용자 트래픽과 수집 트래픽을 분리하고, 계정·IP 단위 한도를 겁니다.
- **연동 엔드포인트에 레이트리밋·WAF·요청 스키마 검증**을 겁니다. 새 연동은 대개 새 호스트·새 경로로 열리므로 기존 방어 규칙 밖에 생깁니다.
- **제휴·입점사 API 키의 로테이션 순서**를 문서로 미리 정해 둡니다. 사고 때 어느 키부터 폐기할지 즉석에서 정하면 정상 제휴사까지 끊깁니다.

### 사고 대응 준비

- **사고 인지 시각 기록 절차**: 24시간·72시간 신고 시계의 시작점입니다.
- **"점검" → "사고" 전환 문구 템플릿**: 이번 공지처럼 초기 안내와 사고 안내가 갈라지면, 이용자는 첫 공지를 기준으로 판단합니다. 전환 시 이전 안내를 지우지 말고 이력으로 남깁니다.
- **상태 페이지·고객센터·입점사 공지 채널을 한 번에 갱신하는 절차**.
- **개인정보 유출 판정 기준**(항목·암호화 여부·규모)을 미리 문서화합니다. 조사 중 판단이 흔들리면 신고 시한을 넘깁니다.
